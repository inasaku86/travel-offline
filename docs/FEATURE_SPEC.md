# Travel-Offline — Feature Specification

本ドキュメントは README のコンセプトを、実装可能な粒度まで落とした機能仕様（MVP 優先）である。

## 1. プロダクトゴール

指定アプリをブロックしているあいだの **オフライン時間** と **移動軌跡** を記録し、「その旅でどれだけオフラインで動いたか」を実績として振り返り・シェアできるようにする。

成功の定義（MVP）:

- ユーザーがチャレンジを開始し、対象アプリがブロックされる
- ブロック中の経過時間が正確に計測される
- 移動軌跡が地図上に残る
- 終了時に「時間＋距離」のシェア画像を1枚出せる

## 2. 対象ユーザーと利用シーン

| ペルソナ | シーン |
|---|---|
| バックパッカー | 数日〜数週間の旅で、SNS/ブラウザ依存を抑えたい |
| 日帰りハイカー | 半日の外出で「スマホを見ない時間」を可視化したい |
| デジタルデトックス志向 | 都市部でも短時間チャレンジを繰り返し、ストリークを伸ばしたい |

前提: ユーザーは位置情報と Screen Time（iOS）権限を許可する。

## 3. コア体験フロー

```
ホーム
  → チャレンジ設定（ブロック対象アプリ選択）
  → 開始確認（権限チェック）
  → チャレンジ中（タイマー＋簡易地図）
  → 終了
  → サマリー（時間 / 距離 / 地図）
  → シェア画像生成・保存 / SNS投稿
```

### 3.1 チャレンジ開始

1. ブロック対象アプリ（またはカテゴリ）を選択する
2. 必要な権限（Screen Time / 位置情報 / バックグラウンド）が揃っているか確認する
3. 未許可なら設定導線を出す。揃っていればチャレンジ開始
4. 開始時刻を記録し、タイマーと位置記録を開始する

**受け入れ条件**

- 権限不足のまま開始できない
- 開始直後にホームに「チャレンジ中」状態が表示される
- ブロック対象アプリ起動時にブロック画面（OS提供）が出る

### 3.2 チャレンジ中

- 経過時間をリアルタイム表示（時:分:秒）
- 現在の移動距離（概算）を表示
- 簡易な現在位置 / これまでの軌跡プレビュー
- 「終了」操作のみで終了できる（誤タップ防止の確認ダイアログあり）

**受け入れ条件**

- アプリをバックグラウンドにしても計測が継続する（可能な範囲）
- 端末ロック中も位置取得が継続する（OS制約内）
- 強制終了後の再起動でチャレンジ状態を復元できる

### 3.3 チャレンジ終了

1. 終了確認
2. タイマー停止・最終位置記録
3. サマリー生成: オフライン時間、移動距離、開始〜終了時刻、軌跡地図
4. 履歴に保存
5. シェア画像を生成できる

**受け入れ条件**

- 終了後にブロックが解除される
- サマリー値が履歴一覧から再表示できる
- シェア画像に少なくとも「時間」「距離」「日付」が含まれる

## 4. 機能詳細

### F1. アプリブロック

| 項目 | 内容 |
|---|---|
| 目的 | チャレンジ中、指定アプリの利用を妨げる |
| iOS | Screen Time API（FamilyControls / ManagedSettings / DeviceActivity） |
| Android（後続） | AccessibilityService + オーバーレイ（方針のみ。MVP外） |
| 選択単位 | 個別アプリ。将来カテゴリ選択を検討 |
| デフォルト候補 | SNS / ブラウザ / マップ系（初回はおすすめリスト提示） |
| 例外 | Travel-Offline 自体はブロック対象にできない |

**エッジケース**

- Screen Time 権限取り消し → チャレンジを強制終了し理由を表示
- ブロック対象ゼロでの開始は不可
- OSの制約で完全ブロックできないケースは既知制限としてオンボーディングで明示

### F2. オフライン時間の計測・ストリーク

| 項目 | 内容 |
|---|---|
| 計測単位 | 秒精度で記録し、表示は「◯時間◯分」中心 |
| セッション | 1回の開始〜終了を1チャレンジ |
| 日次集計 | その日に完了したチャレンジ合計時間 |
| ストリーク | 「1日あたり最低 N 分」のオフラインを達成した連続日数（MVP: N=30分、設定変更は後続） |
| 中断 | ユーザー終了 / 権限喪失 / クラッシュ後の未復元タイムアウト |

**表示**

- ホーム: 今日の合計、現在のストリーク日数
- 履歴: チャレンジごとの時間

### F3. GPS 移動軌跡

| 項目 | 内容 |
|---|---|
| 取得 | Core Location（バックグラウンド） |
| 精度 | バッテリーと精度のバランス（significant / 数十メートル間隔を目安） |
| 記録内容 | 緯度経度、時刻、（任意）水平精度 |
| 距離 | 点列の累積ハバースイン距離。精度の悪い点は間引き |
| 地図 | Mapbox または MapLibre でポリライン描画 |

**エッジケース**

- 屋内・トンネルなどで欠測 → 直線補完せず、取得できた点のみ結ぶ
- 位置権限が「使用中のみ」の場合 → バックグラウンド継続のため「常に」を要求
- 旅の長時間チャレンジで点数が増える → 間引き / 簡略化して描画負荷を抑える

### F4. シェア画像

| 項目 | 内容 |
|---|---|
| 出力 | 正方形（SNS投稿向け）1テンプレートから開始 |
| 必須要素 | アプリ名、日付、オフライン時間、移動距離、軌跡地図（または静的マップ） |
| 操作 | 画像保存 / システム共有シート |
| 非目標（MVP） | 複数デザイン切替、動画、自動投稿 |

### F5. 履歴・実績

- チャレンジ一覧（新しい順）
- 詳細: 時間、距離、地図、開始/終了時刻
- 削除: 個別削除（MVPで可）
- 将来: 月次サマリー、バッジ、公開プロフィール

### F6. オンボーディング / 権限

初回起動で順に説明する:

1. コンセプト（ブロック中の体験を楽しむ）
2. Screen Time 許可
3. 位置情報（常に許可）の説明
4. サンプルのおすすめブロックセット

スキップ可能だが、チャレンジ開始時に未許可なら再要求する。

## 5. 画面一覧（MVP）

| 画面 | 役割 |
|---|---|
| オンボーディング | 権限とコンセプト説明 |
| ホーム | 状態（未開始/チャレンジ中）、今日の合計、ストリーク、開始ボタン |
| アプリ選択 | ブロック対象の選択 |
| チャレンジ中 | タイマー、距離、終了 |
| サマリー | 結果表示、シェア、履歴保存確認 |
| 履歴一覧 | 過去チャレンジ |
| 履歴詳細 | 地図＋数値 |
| 設定 | 権限状態、ストリーク閾値（後続）、アカウント |

## 6. データモデル（概略）

```
User
  id, createdAt, streakCount, streakUpdatedOn

Challenge
  id, userId, status (active|completed|aborted)
  startedAt, endedAt
  blockedAppTokens / identifiers
  durationSeconds
  distanceMeters
  pathSimplified (座標列 or Storage 参照)
  shareImageUrl (optional)

LocationPoint (ローカル優先、必要ならクラウド同期)
  challengeId, lat, lon, recordedAt, accuracy
```

MVP では端末ローカル保存を優先し、Firebase 同期はログイン後のバックアップ用途でもよい。

## 7. 非機能・制約

- **プライバシー**: 軌跡はユーザーの明示操作なしに公開しない。シェアはローカル生成画像の共有が基本
- **バッテリー**: 長時間GPSの影響を設定または開始時に注意表示
- **オフライン動作**: チャレンジ計測自体はネット不要。地図タイル・シェア用静的マップはオンライン時に最適化
- **アカウント**: MVPは匿名/端末ローカル可。Firebase Auth は同期導入時

## 8. MVP スコープ

### Must（TestFlight までに入れる）

- [ ] チャレンジ開始/終了
- [ ] 指定アプリのブロック（iOS Screen Time）
- [ ] 経過時間計測と日次合計
- [ ] GPS軌跡記録と地図描画
- [ ] サマリー＋シェア画像1種
- [ ] 履歴の一覧/詳細

### Should（直後のイテレーション）

- [ ] ストリーク表示（1日30分ルール）
- [ ] チャレンジ中の簡易ライブ地図
- [ ] クラッシュからのアクティブチャレンジ復元

### Later

- [ ] Android 版
- [ ] カスタムシェアテンプレート
- [ ] ソーシャルフィード / 公開プロフィール
- [ ] マップアプリをブロック対象にした場合の代替ナビ連携

## 9. 既知のプロダクト上の論点

1. **マップをブロックすると旅のナビが困る** — MVPではマップをブロック候補に含めるがデフォルトOFF。代替手段の案内は Later
2. **「オフライン」の定義** — 本アプリでは「指定アプリを使えない時間」をオフライン時間と定義する（機内モード必須ではない）
3. **ストリークの厳しさ** — 初期は1日30分。旅行者向けに「旅モード」（滞在期間まとめ）は Later

## 10. 受け入れシナリオ（例）

**シナリオ A: 半日ハイク**

1. ユーザーが Instagram / Safari / Chrome をブロック対象に選ぶ
2. 4時間チャレンジを実施し、12km 歩行
3. 終了後、シェア画像に「4時間 / 12km」と軌跡が載る

**シナリオ B: 権限不足**

1. 位置情報が拒否された状態で開始を試みる
2. 開始できず、設定アプリへの導線が表示される

**シナリオ C: ストリーク**

1. 3日連続で各日30分以上の完了チャレンジがある
2. ホームにストリーク「3日」と表示される
